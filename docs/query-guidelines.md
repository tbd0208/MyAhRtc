# Oracle·MyBatis 조회 기준

## 검색 조건

- 날짜 파라미터는 SQL 안에서 컬럼을 문자열로 바꾸지 않고 `TO_DATE`로 바인드값을 변환합니다.
- 종료일은 `컬럼 < TO_DATE(종료일, 'YYYYMMDD') + 1`을 우선 사용합니다.
- 차량번호 전체, 뒤 4자리, 차대번호 검색을 하나의 광범위한 조건으로 섞기보다 입력 형태별 SQL 분기를 검토합니다.
- `LIKE '%값%'`이 불가피한 일반 검색은 `INSTR`과 실행계획을 비교하되, 어느 쪽이든 일반 B-Tree 인덱스 범위검색을 보장하지는 않습니다.
- 선택 조건이 명확히 다른 경우 MyBatis `choose`를 이용해 옵티마이저가 단순한 SQL을 보게 합니다.

## 페이징

1. 필수 검색 테이블에서 대상 키와 정렬 순서를 확정합니다.
2. `ROW_NUMBER`로 현재 페이지 키를 가져옵니다.
3. 페이지 키에만 부가 테이블, 코드명, 최신 이력, 집계를 조인합니다.
4. 전체 건수 쿼리는 화면 표시 컬럼을 계산하지 않습니다.

## 엑셀

페이징 화면의 '20건이므로 빠른' 구조를 그대로 대량 엑셀에 적용하면 부가 조회가 행 수만큼 확대될 수 있습니다. 엑셀은 다음을 별도로 확인합니다.

- 스칼라 함수 반복 호출
- 행별 상관 서브쿼리
- 코드명 변환
- JSON 집계
- 불필요한 정렬
- 메모리와 네트워크 전송량

## 인덱스

인덱스 제안은 실제 건수, 선택도, 기존 인덱스, DML 비용과 실행계획을 본 뒤 확정합니다. 참고 SQL에 인덱스 생성을 자동 포함하지 않은 이유입니다.
