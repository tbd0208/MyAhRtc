# 아키텍처 원칙

## 1. 점진적 적용

기존 기능을 한 번에 교체하지 않고 기존 매퍼와 V2 매퍼를 분리해 사용자 ID 또는 세션 토글로 검증합니다. 검증 완료 후 호출부를 순차 전환합니다.

## 2. 조회 최적화

- 검색과 페이징에 필요한 테이블을 먼저 조회합니다.
- 코드명, 최신 이력, 집계와 같은 부가 정보는 페이징된 키에만 결합합니다.
- 엑셀 다운로드는 페이징 쿼리를 그대로 재사용하지 않고 대량 조회 실행계획을 별도로 확인합니다.
- Oracle 날짜 종료 조건은 가능한 한 `< 종료일 + 1`로 표현합니다.
- 사용자 입력 컬럼에 함수를 적용하기보다 바인드값을 변환해 인덱스 사용 가능성을 보존합니다.

## 3. 손익과 비용

손익 계산식은 Java의 순수 계산과 DB 조회를 분리합니다.

```
판매가 - 매입총액 - 상품화비용 - 세금/수수료
```

상품화비용은 `RTC_CAR_COST_MNG`에서 집계하되, 데이터량과 호출 빈도가 증가하면 차량별 합계 스냅샷을 별도 검토합니다. 트리거를 사용할 경우 원본 비용 변경과 합계 갱신이 하나의 트랜잭션에서 수행되는지, 재집계 복구 수단이 있는지 확인합니다.

## 4. 권한

데이터 조회 범위와 필드 노출 권한을 분리합니다.

- 데이터 범위: 전체 → 회사 → 사업부 → 부서 → 본인
- 보호 필드: 매입채널, 매입가, 마진, 매입사원
- `AR_RTC_BUYCH_BLND`: 요청 시점에 계산된 매입채널 마스킹 기준값
- 차량별 예외는 행 단위 판정 결과로 결합합니다.

## 5. 보안

실제 계정, DB 주소, 운영 URL, 고객정보, 내부 IP와 인증키는 저장소에 커밋하지 않습니다.
